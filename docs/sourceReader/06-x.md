# 06. `github.com/go-gost/x`：主要实现与组装过程

本文对应版本：`github.com/go-gost/x v0.12.5`。

`x` 是 GOST 的主要实现仓库。它把 `core` 中的接口落实为可运行对象，并负责把配置转换成 Listener、Handler、Router、Route、Dialer 和 Connector。

## 找到源码

```bash
go list -m -f '{{.Dir}}' github.com/go-gost/x
```

下文使用 `x/...` 表示该目录中的相对路径。

## 与 HTTP 请求主线相关的目录

```text
x/
├── config/
│   ├── parsing/        # Config → 各类对象
│   └── loader/         # 按依赖顺序解析并写入 registry
├── registry/           # 线程安全的全局注册表
├── listener/tcp/       # 接受浏览器的 TCP 连接
├── service/            # accept 循环；每连接启动一个 goroutine
├── handler/http/       # 读取 HTTP 请求并执行代理
├── chain/
│   ├── router.go       # DNS、路由选择、重试和超时
│   ├── route.go        # 直连或逐节点建立代理链
│   └── transport.go    # 组合 Dialer 与 Connector
├── dialer/             # 连接代理节点的底层方式
└── connector/          # 在代理节点上请求下一跳/目标的协议
```

## `loader.Load`：配置变成对象

文件：`x/config/loader/loader.go`

当前仓库的 `program.Start()` 调用：

```go
loader.Load(cfg)
```

loader 按依赖顺序注册：

```text
logger / auther / bypass / resolver / limiter 等叶子组件
→ hop
→ chain
→ service
```

顺序很重要。解析 service 时需要按名字取得 chain、resolver、limiter 等对象，所以这些依赖必须先进入 registry。

### 热重载与服务替换

服务构造时 listener 会绑定端口。旧服务若仍占用 `:8080`，新服务就无法绑定同一端口。因此 loader 在重新解析 services 前先：

```text
遍历 ServiceRegistry
→ Unregister
→ 若对象实现 io.Closer，则 Close
→ 旧 listener 释放端口
→ 创建并注册新 service
```

这补充了 `03-program.md` 留下的问题：当前版本重载时旧业务服务由 registry 的 `Unregister` 间接关闭。

## `x/registry`：接口的具体实现

`registry[T]` 内部使用 `sync.Map`：

```go
type registry[T any] struct {
    m sync.Map
}
```

关键行为：

- `LoadOrStore` 保证同名注册不会被悄悄覆盖；
- `GetAll` 返回一个普通 map 快照；
- `Unregister` 会先检查对象是否实现 `io.Closer`，若实现则调用 `Close`。

全局存在多套带具体类型的注册表：

```go
listenerReg  Registry[NewListener]
handlerReg   Registry[NewHandler]
serviceReg   Registry[service.Service]
chainReg     Registry[chain.Chainer]
```

空白导入触发组件 `init()` 后，保存的是构造器。例如 HTTP Handler：

```go
registry.HandlerRegistry().Register("http", NewHandler)
```

配置 parser 之后才能按 `"http"` 取得这个函数并创建对象。

## TCP Listener：客户端连接的入口

文件：`x/listener/tcp/listener.go`

初始化过程大致是：

```text
读取 metadata
→ net.ListenConfig.Listen("tcp", addr)
→ 可选 TCP keepalive
→ 包装 PROXY protocol
→ 包装 metrics / stats / admission / limiter
→ 保存到 l.ln
```

`Accept()`：

```go
conn, err := l.ln.Accept()
```

然后再给连接套一层 traffic limiter wrapper，最终返回 `net.Conn`。

此时只完成了浏览器到 GOST 的入站连接，没有访问目标网站。

## `x/service.defaultService`：accept 循环

文件：`x/service/service.go`

核心结构：

```go
type defaultService struct {
    listener listener.Listener
    handler  handler.Handler
    // ...
}
```

`Serve()` 持续执行：

```text
listener.Accept()
→ 为连接建立 session context
→ admission 检查
→ wg.Add(1)
→ 启动 goroutine
     → handler.Handle(ctx, conn)
```

这意味着多个客户端连接可以并发处理。`Serve()` 结束前通过 `defer wg.Wait()` 等待已经启动的 Handler goroutine 返回。

临时 Accept 错误会指数退避：

```text
1s → 2s → 4s → 上限 5s
```

不可恢复错误或 listener 被关闭时，`Serve()` 返回。

## HTTP Handler：从字节流得到目标地址

文件：

- `x/handler/http/handler.go`
- `x/handler/http/util.go`
- `x/handler/http/proxy.go`
- `x/handler/http/connect.go`

### `Init`

HTTP Handler 构造 `http.Transport`：

```go
h.transport = &http.Transport{
    DialContext: h.dial,
    // ...
}
```

这是访问目标网站的关键注入点。标准库 Transport 负责 HTTP 报文发送、连接复用、读取响应；当它需要新建 TCP 连接时，不调用默认 dialer，而调用 GOST 的 `h.dial`。

### `Handle`

```go
br := bufio.NewReader(conn)
req, err := http.ReadRequest(br)
return h.handleRequest(ctx, conn, req, ...)
```

`http.ReadRequest` 从客户端连接读取：

- 请求行；
- Header；
- Body；
- URL；
- Host。

`bufio.Reader` 可能预读多余字节，所以代码用 `NewReadWriteConn(br, conn, conn)` 包装连接，确保后续读取先消费缓冲区，不能直接丢掉 `br`。

### `normalizeRequest`

它从请求中得到：

```go
type NormalizedRequest struct {
    Network string // tcp 或 udp
    Addr    string // host:port
}
```

普通 HTTP 代理请求示例：

```http
GET http://example.com/news HTTP/1.1
Host: example.com
```

结果通常是：

```text
Network = tcp
Addr    = example.com:80
```

HTTPS 代理通常先收到：

```http
CONNECT example.com:443 HTTP/1.1
Host: example.com:443
```

结果是 `example.com:443`。

### `handleRequest` 分流

完成认证、合法性和 bypass 检查后：

```text
network == udp        → handleUDP
method != CONNECT     → handleProxy
method == CONNECT     → handleConnect
```

## Router：统一建立出站连接

文件：`x/chain/router.go`

`Router.Dial(ctx, network, address)` 执行：

1. 取出 host 并记录指标；
2. 根据 resolver/hosts 解析 `address`；
3. Chainer 按目标选择 Route；
4. 没有 Route 时使用 `DefaultRoute`；
5. 调用 `route.Dial`；
6. 失败时按配置重试，每次都有独立 timeout。

值得注意：Router 会把主机名解析为 `ipAddr` 后传给 Route，同时以 `WithHostRouteOption(address)` 保留原始主机信息用于路由选择。

## 直连路径

文件：`x/chain/route.go`

未配置代理链时：

```go
DefaultRoute.Dial(ctx, network, address)
```

它最终通过 `x/internal/net/dialer.Dialer.Dial` 建立 socket。可以把它近似理解成增强版 `net.Dialer.DialContext`，额外支持网卡、network namespace、socket mark 等能力。

直连主线：

```text
Handler
→ Router.Dial
→ DefaultRoute.Dial
→ internal net Dialer
→ 操作系统 socket connect
→ 目标网站
```

## 代理链路径

选中带节点的 `chainRoute` 时：

1. `connect()` 对第一个 Node 调用 `Transport.Dial`；
2. 调用第一个 Node 的 `Transport.Handshake`；
3. 对后续每个 Node：
   - 使用前一 Node 的 `Transport.Connect` 请求连接下一 Node；
   - 使用当前 Node 的 `Transport.Handshake`；
4. 到达最后一个 Node 后，`chainRoute.Dial` 调用最后节点的 `Transport.Connect` 请求最终目标。

```text
GOST
  │ Transport.Dial + Handshake
  ▼
Node 1
  │ Transport.Connect(Node 2) + Node 2 Handshake
  ▼
Node 2
  │ Transport.Connect(target)
  ▼
目标网站
```

## `Transport`：组合 Dialer 与 Connector

文件：`x/chain/transport.go`

```go
type Transport struct {
    dialer    dialer.Dialer
    connector connector.Connector
}
```

- `Transport.Dial` 委托给 dialer；
- `Transport.Handshake` 依次尝试 dialer Handshaker 和 connector Handshaker；
- `Transport.Connect` 委托给 connector。

类型断言：

```go
if hs, ok := tr.dialer.(dialer.Handshaker); ok {
    // ...
}
```

表示 Handshake 是可选能力。对象实现额外接口时才执行。

## 一个容易误读的 `directDialer`

`x/dialer/direct.Dial` 返回的是占位 `conn`，不是直接访问目标网站的真实 socket：

```go
func (d *directDialer) Dial(...) (net.Conn, error) {
    return &conn{}, nil
}
```

真正直连目标发生在 `x/connector/direct.Connect`：

```go
return cOpts.Dialer.Dial(ctx, network, address)
```

因此不要根据包名猜行为。要沿着 `Transport.Dial → Handshake → Connect` 全部读完。

## `Close` 与请求结束

`defaultService.Close()` 会：

1. 若 Handler 实现 `io.Closer`，关闭 Handler；
2. 关闭 observer；
3. 关闭 listener。

HTTP Handler 的 `Close()` 会取消它的后台统计 goroutine。listener 关闭后，阻塞中的 `Accept()` 返回，Service 的 accept 循环结束。

## 建议下断点的位置

使用 Delve 时，可依次在这些函数下断点：

```text
x/service.(*defaultService).Serve
x/handler/http.(*httpHandler).Handle
x/handler/http.(*httpHandler).handleRequest
x/handler/http.(*httpHandler).proxyRoundTrip
x/handler/http.(*httpHandler).handleConnect
x/handler/http.(*httpHandler).dial
x/chain.(*Router).Dial
x/chain.(*defaultRoute).Dial
x/chain.(*chainRoute).Dial
```

依赖位于 module cache，通常是只读目录。阅读和下断点没有问题；若要修改实验，建议用 `go mod edit -replace` 指向自己克隆的依赖仓库，而不是直接改 module cache。
